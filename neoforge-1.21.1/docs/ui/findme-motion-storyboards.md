# FindMe AUI 动效分镜提案

状态：**待用户视觉验收，尚未据此修改动画代码。**

日期：2026-07-22

## 目标

保留已经确认的明日方舟式黑 / 白 / 青蓝静态视觉，只借用 Persona 5 的动作语法：明确锚点、局部结构侵入、旧新状态共存、不同语义使用不同运动、最终姿势先行。禁止再用一个普通的全屏翻页覆盖所有操作。

本文件描述的是镜头和交互因果，不锁死具体 CSS。用户确认分镜后，再由一个共享阶段控制器实现各操作的不同锚点与几何。

## 全局动作规则

1. **先响应，再计算。** 输入后 `0–50ms` 内必须出现按压、抬起、青蓝切口或标题锚点；网络刷新和 3D 创建不能阻塞第一帧。
2. **外壳尽量不动。** 顶部类别、页面标题、左侧导航或世界背景只有在语义确实改变时才参与；兄弟内容切换不重播整页打开。
3. **必须共存。** 每段结构动画至少有一帧能同时看见旧内容的一部分和新结构的一部分。
4. **交换点可见但不露馅。** 数据在最大压缩、折叠或切线覆盖处交换，不能先闪出终态。
5. **3D 晚于结构。** 动画开始时冻结当前预览；新页面文字和卡片骨架到位后再启用实时 3D。
6. **终态最清楚。** 倾斜、错位、阴影和高对比只用于运动；停下后名字、数量和操作按钮必须比运动帧更清楚。
7. **可逆不等于倒放一切。** 返回沿同一空间关系逆转；删除、移除、插入等改变集合的操作使用自己的出入场语义。
8. **声音解释动作。** 轻按、纸面切开、卡片落槽、危险确认分别使用短促相关声音；最强瞬态落在动作原因或交换点。

### 推荐节奏

| 阶段 | 起始建议 | 说明 |
|---|---:|---|
| 输入承认 | `0–45ms` | 按钮/行/卡片先有反应 |
| 主转移 | `45–190ms` | 旧、新结构共存并移动 |
| 数据交换 | `120–190ms` 内的最大转移帧 | 由具体分镜决定 |
| 新结构展开 | `170–280ms` | 第一可读焦点先到 |
| 安定 | `250–340ms` | 次级文字和 3D 预览恢复 |

不是所有操作都要达到 340ms。右键菜单和局部开关应明显更短；首屏打开和详情变形可以稍长。

## 1. 打开 / 关闭管理页

语义：从世界进入 FindMe 的管理空间。

锚点：管理页标题 + 当前类别文字/青蓝标记。不要使用无来源的全屏纸面。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 世界 | 世界完整；按键刚触发 | 输入立即锁定重复打开；不创建全部 3D |
| F1 标题刺入 | 标题和一小段青蓝斜线先出现在最终位置附近，像在世界上划出入口 | 世界仍占绝大部分；标题是动作原因 |
| F2 左侧生长 | 深灰侧栏从标题下方展开；不是整块淡入，边缘带一条短青蓝折线 | 世界从侧栏外和工作区缝隙可见 |
| F3 工作区接力 | 浅色工作区从侧栏边界向右展开；顶部类别在工作区前缘之后依次到位 | 旧世界仍从未覆盖区域透出；页面数据在此准备但不启用预览 |
| F4 卡片发出 | 编队行先出现；六张卡片骨架从当前编队行方向依次落入，不一起淡入 | 名字、状态先可读；3D 占位仍静止 |
| F5 安定 | 数量、次级文字到位；实时 3D 分批启用 | 解锁输入；缓存刷新可在此后进行 |

关闭：F5 → F4 的卡片收回当前编队行；工作区退回侧栏边界；侧栏收回标题；最后标题/青蓝线从世界上抽走。世界必须在结构缝隙扩大时逐步恢复，不能先盖黑屏。

验收重点：第一帧是否立即响应；满 6 卡时是否无卡顿；关闭是否真的回到标题锚点。

## 2. 编队之间切换

语义：保留同一管理空间，只替换当前编队的六个成员。

锚点：左侧被点击的编队行和它左侧的青蓝选中线。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 当前编队 | 当前行与六张卡片完整 | 只锁定编队/卡片区域，不冻结顶部关闭键 |
| F1 行响应 | 新编队行上抬 1–2px，青蓝线从中点向上下伸开；旧选中线开始收短 | 玩家清楚看到动作来自哪一行 |
| F2 收档 | 旧六卡按“离编队行越远越先动”的短错峰，缩成窄档案片并向新选中行的右缘收束 | 旧卡仍可辨认；页面外壳、顶部类别、仓库按钮完全不动 |
| F3 交换 | 旧卡压成一叠贴在行右缘；队名/编号做一次短纵向滚动；此处交换成员数据 | 3D 冻结；叠片遮住结构变更 |
| F4 发牌 | 新卡从同一叠片依次向六个槽位发出；前两张出现时，后几张仍在叠中 | 新旧通过同一个锚点完成视线接力 |
| F5 安定 | 青蓝线稳定在新行；卡片恢复完整深度，3D 分批开启 | 解锁区域，保持原滚动位置 |

禁止：整页仓库式翻页、整个左侧背景重播、所有六卡同速横滑、旧卡先消失再显示新卡。

如果游戏内“收成一叠”仍显繁琐，降级方案是保留 F1/F3/F4，只把六卡压成同一条横向档案带；仍不得回退成全屏翻页。

## 3. 坐骑 / 载具 / 伙伴分类切换

语义：在同一管理外壳中替换数据域，变化范围大于编队切换，但小于进入新页面。

锚点：顶部被点击的类别文字和其下方青蓝线。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 当前类别 | 当前下划线、左侧编队和卡片完整 | 冻结类别重复点击 |
| F1 切线伸长 | 新标签按下；青蓝下划线从标签中心向左右伸长，略超出文字 | 顶部直接承认输入 |
| F2 旧内容退线 | 伸长线沿内容区形成一条斜切边；旧卡片和旧编队文字朝切边缩短/变暗 | 标题、关闭和仓库位置保持不动 |
| F3 数据交换 | 切边位于内容区中部，左侧旧行仍残留一部分，右侧已露出新类别第一批骨架 | 在切边最宽处交换类别数据和数量 |
| F4 新内容展开 | 新编队从切边向左落位，新卡片从切边向右展开 | 旧内容最后碎片退出，形成可见接力 |
| F5 线归位 | 大切边收回顶部，成为新标签的普通青蓝下划线 | 启用新预览并解锁 |

方向：切换到右侧标签时边界向右推进；切换到左侧标签时相反。方向必须匹配标签相对位置。

## 4. 进入 / 退出仓库

语义：从“六个编队成员”进入“完整集合档案”。

锚点：仓库按钮 + 黄色数量块。仓库不是普通下一页，而是从数量入口抽出完整档案。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 管理页 | 六卡和仓库数量完整 | 点击仓库后锁定内容区 |
| F1 数量块响应 | 黄色数量块向前抬起并短促错切，数字保持可读 | 动作明确来自仓库入口 |
| F2 收束 | 六卡缩小为正方形档案缩略片，沿轻微弧线向数量块后方叠入 | 左侧编队仍存在，世界/外壳不重播 |
| F3 档案抽出 | 数量块与叠片横向拉开，左侧编队列在同一结构中变形为 `01/02/03` 筛选；在最大重叠处交换 DOM | 管理卡最后一角仍可见，新仓库第一行骨架已出现 |
| F4 网格发牌 | 仓库卡片按行、短错峰落入网格；搜索框由原鼠标提示位置展开 | 第一屏卡片先有文字和静态占位 |
| F5 安定 | 数量和滚动条到位；只启用 viewport 内 3D | 解锁；下面未进入 viewport 的实体不创建预览 |

退出严格逆向：网格回到数量块，筛选列恢复编队列，六卡从数量入口发回。无需重播管理页首开动画。

## 5. 卡片竖版 / 详情切换

语义：同一实体卡片从摘要变成完整观察对象；卡片本身就是详情入口。

锚点：玩家左键点击的实体卡片。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 竖卡 | 卡片正常，3D 为缩略预览 | 记录卡片最终屏幕矩形 |
| F1 抬起 | 卡片整体上移 2–3px，阴影拉开；邻卡向两侧让出极小空间 | 卡内文字保持完整，不拆子元素单独飞 |
| F2 展开 | 卡片以前缘/选中侧为轴变宽变高；原名字条仍钉在同一边，摘要背景演化为详情背景 | 旧卡轮廓仍能识别，新详情区域已从卡后出现 |
| F3 结构交换 | 卡片覆盖目标详情矩形；在模型被安全遮挡/冻结时交换详情 DOM | 不允许 3D 穿到按钮文字前面 |
| F4 详情落位 | 操作按钮和属性条从卡片边缘依次抽出；模型按最终构图重新缩放 | 先文字、后模型 |
| F5 安定 | 详情完整，模型实时 | 左键再次触发逆向恢复竖卡 |

返回时邻卡先准备接位，详情收回原卡矩形后再恢复缩略 3D；不能让模型尺寸先跳变。

## 6. 小屋：家园生物 / 家园伙伴切换

语义：同一小屋内，在“分配居民的双栏”与“已绑定小屋的伙伴档案”之间切换。

锚点：左侧被选中的 `01/02` 行 + 中间分界线。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 当前视图 | 左侧灰色背景、标题、双栏/卡片完整 | 保留小屋标题和关闭 |
| F1 侧栏回应 | 新行青蓝线展开；左侧整块灰色 sheet 只做一次很短的深浅翻面，不消失 | 标签从上到下依次强调，避免一起跳出 |
| F2 双栏合拢 | 左右内容分别向中间分界线折叠；搜索框和数量跟随各自栏，不独立漂移 | 旧双栏仍可辨识 |
| F3 中轴交换 | 两栏压到中轴两侧；数据与布局在此交换；新视图第一条标题已从轴后露出 | 中轴是连续视觉原因，不用全屏遮罩 |
| F4 新视图展开 | 新的仓库式卡片网格从中轴向两侧展开；左侧文案按从上到下短错峰恢复 | viewport 外不创建 3D |
| F5 安定 | 搜索框、数量和列表区域与仓库同坐标基线；预览启用 | 解锁滚动和拖动 |

左侧灰色背景首次打开页面时从标题下向下展开；内部 `01/02` 切换只做 F1 的短翻面，不能每次重播整个侧栏打开。

## 7. 右键菜单 / 重命名

语义：在指针局部打开动作列表；重命名是菜单几何内的下一层，而不是另开全屏页面。

锚点：鼠标右键按下位置是菜单**纵向中心**基准点。默认向右打开；右侧空间不足时整体翻到左侧。

| 帧 | 画面 | 旧/新共存与交互 |
|---|---|---|
| F0 指针 | 页面不动 | 保存指针和目标 UUID |
| F1 切口 | 指针处出现 1–2px 青蓝短切口/黑色纸边 | 目标卡片只做轻微选中，不重排 |
| F2 菜单展开 | 黑色菜单从指针中心同时向上、向下展开，并朝可用侧伸宽 | 菜单顶部不是鼠标锚点；overlay 位于 3D 上方 |
| F3 条目到位 | 条目沿展开方向短错峰出现；危险项最后出现且保持红色识别 | 解锁菜单内部输入 |

重命名子流程：

| 帧 | 画面 | 交换 |
|---|---|---|
| R0 | 主菜单条目完整 | 点击“重命名” |
| R1 | 被选条目向内折，其他条目压成窄条 | 输入框尚未获得焦点 |
| R2 | 菜单压到指针中心附近的窄纸片 | 在最窄处切换到重命名 DOM |
| R3 | 同一菜单几何反向展开为标题 + 黑底白字输入框 + 确认/返回 | 展开完成后才 focus，focus 背景保持与未聚焦一致 |
| R4 | 确认时输入框压成名字标签并回到主菜单/关闭 | 服务端失败则短促红色拒绝，不销毁输入内容 |

关闭时向指针中心收回。边缘翻转只改变横向侧别，不改变纵向中心锚点。

## 8. 卡片加入 / 移除 / 拖动排序

### 加入编队

锚点：被选仓库卡 + 目标编队槽位。

1. F0：目标槽位边缘先亮青蓝。
2. F1：相邻卡片向两侧让出真实空位，不能先覆盖再瞬移。
3. F2：源卡抬起，缩成管理页竖卡比例，沿短弧进入空位；源列表保留空缺/重新排版预告。
4. F3：卡片前缘越过槽位边时执行权威确认；失败则沿原路径退回。
5. F4：卡片轻微压下落槽，青蓝线收回；其他卡片合拢。

### 移除编队 / 解除绑定

锚点：目标卡。

1. F0：危险操作确认完成。
2. F1：卡片上抬，背景与模型冻结成一个整体。
3. F2：卡片向上抽离；卡片清楚越过邻卡后，邻卡才开始合拢。
4. F3：卡片退到列表外并淡出；在被遮挡的中后段执行服务端操作。
5. F4：剩余卡片落位；失败则把原卡从上方插回，而不是刷新整页。

“移除编队”落入仓库；“解除绑定”离开整个集合。二者可以共享抽卡控制器，但危险色、终点和声音不同。

### 长按拖动编队或生物

锚点：被长按卡片和实时目标空位。

1. F0：长按阈值未到，普通卡片不动。
2. F1：阈值达到，卡片整体上抬 2–3px；实时 3D 冻结并替换为稳定缩略图/剪影，所有文字保持一个整体，禁止子文本被裁成一半。
3. F2：手中 ghost 跟随指针，尺寸与最终卡片语义一致；源位置保留占位，不让列表塌缩。
4. F3：进入某目标区时，目标区整体出现浅青蓝底；目标前后的卡片先让位并实时显示落点。判定区域覆盖整栏/整面板，不只覆盖中间小块。
5. F4：放下后 ghost 先压入占位，再更新顺序；卡片轻微回弹，其他卡片稳定。
6. F5：服务端确认失败则保持用户可理解的原顺序，并让 ghost 沿短路径返回源位；成功则持久化且轮盘顺序同步。

编队 6 拖到编队 1：旧 1 顺延为 2；重新打开仍保持。生物 6 拖到 1：轮盘同序。拖动时滚动区域靠近上下边缘可自动滚动，但不能让 ghost 被 viewport 裁剪。

## 实现前用户验收点

请先只看分镜语义，确认以下问题：

- 管理页打开是否采用“标题划开入口 → 侧栏 → 工作区 → 卡片”，而不是整屏翻页。
- 编队切换是否接受“旧六卡收进被选编队行，新六卡从同一行发出”。
- 分类切换是否接受“顶部青蓝下划线变成内容切边”。
- 仓库是否接受“卡片收进黄色数量块，再从数量块抽出档案网格”。
- 详情是否接受“被点卡片本身扩展成详情”。
- 小屋切换是否接受“左右栏向中轴合拢再展开”。
- 右键菜单是否保持指针为纵向中心锚点，并在边缘自动翻侧。

只有这些镜头得到确认后，才开始替换当前游戏动画。当前现有 Java/CSS 动画和测试 JAR均未因本文件发生变化。
