## 1. 项目定位

FindMe 1.3 是一个围绕“绑定、仓库、召唤、收纳、坐骑、载具、伙伴、小屋和恢复”的生物管理模组。

核心目标按优先级排列：

1. 官方生物不能无故丢失。
2. 官方生物不能被重复生成。
3. 所有召唤、收纳、切换和恢复都有清晰的状态与事务边界。
4. 坐骑、载具、伙伴、编队和小屋的操作方式统一。
5. 管理界面使用 ApricityUI 重做，并保持接近原版的视觉风格。
6. 兼容性代码隔离，不能污染普通生物生命周期。

## 2. 明确不做的内容

- 不保留旧的 Java 管理界面。
- 不保留旧的管理界面入口、重复的载具 Tab 页面、旧仓库页面和旧右键菜单实现。
- 不使用 KubeJS 承担 FindMe 管理逻辑。
- 不把技能系统并入正式生物生命周期。
- 不再保留 Emergency Rescue 作为独立的选宠、独立指令或独立主系统。
- 不用实体名称关键词判断生物类型。
- 不创建通用“坐垫给任意载具加座位”功能。
- 不加入护卫编队、护卫自动战斗、多护卫、护卫跨维度无缝追踪等扩展。
- 不增加危险环境能力矩阵；危险环境只对岩浆保留防火判断。
- 不为每个单独生物创建一套完整实体资料。

## 3. 总体架构

正式生物操作统一经过以下流程：

```text
请求
  -> 权限、所有权、冷却、操作锁检查
  -> 解析实体资料和生命周期状态
  -> 获取世界中的实体或保存的快照
  -> 生成安全放置请求
  -> 启动动画/临时控制
  -> 动画报告成功、取消或失败
  -> 生命周期提交正式状态
  -> 写入世界数据
  -> 同步客户端 UI
```

长期代码边界：

```text
server/core/       事件入口、日志、操作锁、实体查找
server/data/       世界数据、玩家记录、快照、备份、迁移
server/lifecycle/  召唤、收纳、部署、切换、旅行和退出清理
server/profile/    实体类型、所有权、移动能力、预览资料
server/animation/  动画、特效、音频、临时动画状态
server/ui/         仓库、编队、轮盘、同步 DTO 和 UI 服务
server/vehicle/    普通载具和 Sable 兼容实现
server/home/       小屋和居民
server/safety/     死亡、Doctor、恢复、完整性检查
server/command/    指令入口和指令适配器
```

不要在生命周期没有稳定前继续拆出大量新顶层包。技能系统保留在独立的 `server/skill/`，默认关闭。

## 4. 权威数据模型

### 4.1 数据归属

FindMe 1.3 的权威数据改为世界 `SavedData`，通过当前存档主世界的 `DimensionDataStorage` 保存。

世界数据包含：

- 玩家 FindMe 注册表。
- 生物完整保存快照和当前生命周期状态。
- 坐骑、载具和伙伴分类。
- 编队、编队名称、顺序和自动加入选项。
- 轮盘当前编队和轮盘页面数据。
- 死亡记录。
- 小屋记录、居民关系和小屋历史恢复信息。
- Doctor 恢复记录、事务记录、全玩家备份和实体恢复墓碑。
- 玩家设置、音效/对白模式和效果设置。
- 实体资料覆盖和整合包作者配置。

玩家 Persistent NBT 和旧 `PlayerCompanionDataMirror` 不再作为运行时权威来源，只在迁移成功后保留为只读恢复来源。

### 4.2 存档隔离

世界 `SavedData` 只属于当前 Minecraft 存档：

- 不影响其他世界。
- 不覆盖其他模组的 SavedData。
- 不把玩家数据写入全局跨存档文件。
- 多人世界中每个玩家仍按 UUID 分开记录。
- 多个小屋和多个玩家的记录共存于同一个 FindMe 世界数据，但权限按所有者校验。

### 4.3 正式生命周期状态

每个注册生物只能有一个正式主状态：

| 状态 | 含义 |
| --- | --- |
| `STORED` | 生物只存在于保存快照中 |
| `DEPLOYED` | 生物作为正式实体存在于世界 |
| `SHOULDER` | 生物正式部署在玩家肩膀上 |
| `HOME_STORED` | 生物属于小屋，但当前以保存状态存在 |
| `HOME_ACTIVE` | 小屋居民已在世界中实体化 |
| `DEAD` | 生物有可恢复的死亡记录 |
| `RECOVERY` | 数据或实体类型存在问题，等待 Doctor/恢复处理 |

以下内容不是主状态：

- 骑乘：由玩家与正式部署实体的乘客关系推导。
- 护卫：绑定在已部署伙伴上的角色引用。
- 召唤、收纳、切换、救援动画：使用操作锁和事务日志。
- `Missing`：Doctor 诊断结果，不得在正常读取时静默写成一个状态。

系统必须保证一个 UUID 不会同时成为世界实体和仓库正式实体。发生冲突时保留可验证的世界实体，旧快照作为恢复墓碑。

## 5. 1.2 到 1.3 数据迁移

1.2 存档升级到 1.3 时，必须自动迁移，不能因为换成世界数据而丢失玩家已经绑定和收纳的生物。

迁移规则：

1. 玩家第一次进入 1.3 时读取旧版 `find_me` Persistent NBT。
2. 只有旧根数据不可用时，才读取 Mirror 或最近有效备份。
3. 迁移注册生物、保存快照、部署状态、坐骑/载具/伙伴类型、编队、轮盘成员、死亡记录、小屋字段、设置、墓碑和备份信息。
4. 写入世界 SavedData 后重新加载并验证 UUID 集合、快照、代数、校验和、记录数量。
5. 验证成功后记录迁移版本、来源、时间、源数据校验和和结果。
6. 中途失败时保留旧数据不动，迁移可以重试。
7. 已经存在权威世界记录时，旧 NBT 永远不能覆盖它。
8. 迁移成功后旧 NBT 只读，不再参与日常恢复，避免已删除生物被旧镜像重新召回。
9. 旧数据中同时存在活体和保存快照时，活体优先，不能生成第二个 UUID。
10. 旧小屋坐标只有在确实对应一个真实小屋方块时才能迁移为小屋关系，否则记录迁移报告并放回普通仓库。

迁移完成后不支持继续把同一个存档降级到 1.2 游玩。

## 6. 实体资料和绑定

### 6.1 统一实体资料

类型级实体资料字段保持精简：

- 分类：`AUTO`、`COMPANION`、`MOUNT`、`VEHICLE`、`DISABLED`。
- 移动方式：`AUTO`、`WALK`、`FLY`、`SWIM`。
- 绑定要求：`OWNER_REQUIRED`、`ALLOW_UNOWNED`、`DISABLED`。
- UI 预览缩放和 Y 偏移。
- 召唤、救援、收纳的默认效果样式和效果缩放。
- 到达声音 ID、音量和音调。

资料解析优先级：

1. 整合包/世界资料覆盖。
2. FindMe 内置兼容资料。
3. 实体接口、属性和运行时能力。
4. 保守的自动结果。

实体资料是类型默认值。单只生物只保存真正的个体覆盖和运行时解析结果。

视觉缩放只影响 UI 和特效，不改变碰撞箱、安全放置或实际移动能力。

### 6.2 未知生物默认规则

未知但符合所有权/驯服条件的模组生物，默认作为伙伴。

只有玩家实际骑上已注册伙伴时，该个体才晋升为坐骑，并进入坐骑/载具共用的单一骑乘位置。不能因为实体注册名看起来像“dragon”“mount”等就自动分类。

### 6.3 资料编辑权限

- 普通玩家只能查看解析结果。
- 管理员可以在实体资料编辑器中修改。
- 整合包作者可以通过世界/服务器资料导出可移植 JSON。
- `ALLOW_UNOWNED` 默认关闭，只有管理员或整合包资料可以启用。
- 不再保留 `customMounts`、`customCompanions`、`customMoveTypes`、`previewScaleOverrides` 多套互相覆盖的旧配置。

### 6.4 绑定

- 名纸绑定普通生物，成功后才消耗。
- 绑定器绑定并保存普通载具或 Sable 载具，成功后才消耗。
- 管理员强制绑定改为准星指向对应生物：`/findme tame mount` 或 `/findme tame companion`，命令不额外接收目标参数。
- 强制绑定仍然必须经过正式注册、UUID 校验、备份和编队分配。

## 7. 坐骑、载具和伙伴轮盘

### 7.1 功能关系

玩家层面，坐骑和载具属于同一个“骑乘功能体”；实现层面仍保留不同控制器。

- 一个骑乘键打开坐骑/载具轮盘。
- 一个伙伴键打开伙伴轮盘。
- 骑乘轮盘内按 `Tab` 在坐骑和载具之间切换。
- 不保留旧的隐藏 Tab 载具管理页面。
- 两个轮盘共用布局、预览、分页、编队标签、输入和 AUI 背景组件。

### 7.2 按键和确认

- 骑乘键短按且当前没有 FindMe 骑乘对象：召唤上次成功使用的注册骑乘对象。
- 当前正在骑注册坐骑/载具时，单次短按不会收纳，防止误触。
- 再次收纳需要在 350 毫秒内完成双击。
- 打开轮盘需要按住按键约 300 毫秒。
- 轮盘悬停只是本地 pending，不立即改服务器数据。
- 松开按键或左键确认 pending 目标。
- 没有 pending 或选择中心区域时取消。
- 选择当前正在骑的对象会执行收纳。
- 选择其他对象会召唤或切换。
- 伙伴轮盘使用同样的 pending、确认和取消逻辑。

### 7.3 占用中的骑乘对象

收纳带有外部乘客的坐骑/载具需要二次确认：

1. 第一次请求只提醒玩家，并为该对象建立 5 秒确认窗口。
2. 5 秒内再次请求才强制收纳。
3. 快捷键本身是双击，因此快捷键场景等于连续两次双击，共四次点击。
4. 轮盘或 AUI 操作也需要调用两次。
5. 收纳前安全处理外部乘客，不把乘客序列化进载具快照。
6. Sable 乘客使用 Sable 专用投影/弹出流程。

## 8. 编队和仓库

### 8.1 编队规则

- 编队数量没有上限。
- 每个编队容量固定为 6，等于轮盘单页容量。
- 只有需要时才创建下一个编队，不能提前创建 8 个。
- 新生物加入时从编队 1 开始寻找第一个允许自动加入且未满的编队。
- 没有可用编队时才创建新编队。
- 玩家手动新建编队也不设上限。
- 编队支持自定义名称和顺序。
- 自动加入新伙伴后不自动切换到它所在编队。
- 编队滚轮只改变本地预览编队，不立即保存或执行生物操作。
- 必须明确选择生物后，才提交编队/成员选择和对应动作。

### 8.2 编队操作

编队右键打开统一右键菜单，至少包含：

- 编队命名。
- 自动加入/不自动加入切换。
- 编队排序。
- 右键删除编队。

删除编队必须二次确认。删除后成员回到对应类别仓库，后续编队顺序向前移动；删除当前编队后进入对应仓库。不能删除导致系统没有任何编队的最后一个编队。

卡片操作统一为：

- 左键：选择/打开详细面板。
- 右键或次要点击：打开上下文菜单。
- 拖拽：只在明确的编队编辑模式下用于移动成员。
- 不使用管理卡片双击。

### 8.3 仓库

仓库数量不设上限，不能因为编队容量为 6 而丢弃多出的生物。

管理界面选择坐骑、载具或伙伴类别后，编队列表和右侧生物仓库同时切换类别，不再另放一个重复筛选器。

## 9. 伙伴部署和护卫

### 9.1 部署上限

- 坐骑和载具共用一个位置，默认只能部署一个。
- 伙伴默认可以部署两个。
- 伙伴上限可配置。
- 护卫占用伙伴位置。
- 如果伙伴上限为 1，且唯一位置被护卫占用，召唤普通伙伴时先收纳护卫，再召唤新伙伴。
- 召唤第三个伙伴时，自动收纳最早部署的非护卫伙伴。
- 如果没有非护卫伙伴，则收纳最早的护卫伙伴。
- 切换护卫时旧护卫先自动收纳，不会降级成普通部署伙伴。

### 9.2 护卫定义

护卫只是玩家骑乘时的装饰性陪伴，不是新的主生命周期状态。

- 只有生物伙伴可以成为护卫。
- Sable、普通载具和坐骑不能成为护卫。
- 玩家骑 Sable 时，生物护卫仍可以跟随 Sable。
- 护卫跟随玩家当前的坐骑/载具作为锚点。
- 玩家收纳坐骑或停止骑乘后，护卫也应收纳。
- 骑乘切换成功后，护卫可以转移到新的骑乘锚点。
- 护卫从伙伴轮盘切换，不放在骑乘轮盘。
- 护卫不能同时是当前骑乘对象。
- 护卫不自动获得额外战斗逻辑。

## 10. 战斗救援

保留伙伴战斗救援，但重新纳入统一伙伴部署和威胁选择流程。

召唤新的救援伙伴时：

- 之前已经部署的伙伴和新到达伙伴一起参与救援。
- 受伙伴部署上限约束。
- 溢出处理顺序与普通召唤相同：先收纳最早的非护卫，再收纳最早的护卫。
- 不因为伙伴之前没有攻击过玩家就排除它。

威胁优先级：

1. 附近正在仇恨/主动攻击玩家的实体。
2. 仍然相关的近期真实攻击者。
3. 距离很近、正在接近且有效的敌对实体。

持续重新评估威胁，旧威胁远离后，附近更直接的威胁可以取代它。

战斗规则：

- 玩家可以误伤自己的绑定伙伴。
- 其他玩家可以杀死你的绑定生物。
- 同一 FindMe 编队内的伙伴不能互相伤害。
- 救援伙伴可以攻击符合威胁条件的其他玩家。
- 不会因为玩家只是靠近就攻击无关玩家。
- 不添加人工减速、削弱、推开等救援副作用。

## 11. 高空和危险环境救援

高空救援不是第二个选宠系统，而是玩家按正常骑乘召唤当前选中坐骑时自动改变表现形式。

触发条件必须同时满足“正在下降”，并满足以下任一条件：

- `fallDistance >= 5`。
- 到安全落点的垂直距离大于 6 格。

落点计算：

- 使用真实碰撞面，不把草、花等空碰撞植物当作地面。
- 正确识别雪层等部分方块的顶部高度。
- 水、岩浆、细雪、危险模组液体和虚空不能直接当作普通安全实地。
- 不能用一个过度复杂的环境能力矩阵。
- 只对岩浆额外检查当前生物是否防火。

处理原则：

- 当前选中的坐骑仍然可以先接住并稳定玩家。
- 如果该坐骑不能在落点安全停留，则接住后立即保存快照、正式收纳并消失。
- 防火坐骑在岩浆环境中通过普通安全放置检查后可以保留。
- 普通陆地坐骑不能留在虚空、细雪或不支持的危险液体中。
- 不自动替玩家寻找另一只坐骑。
- 不把玩家传送回旧位置或附近安全点。
- 不保证坐骑消失后玩家一定存活；玩家进入岩浆/虚空仍需自己承担风险。
- 失败接住路径必须进入统一的“接住后收纳”流程，不能因电影动画失败回调而把坐骑错误标成仍在部署。

高空救援与外部传送收纳规则独立，FindMe 自己的救援、切换、动画和 Sable 投影必须使用 intentional-transfer 标记，避免被自动收纳逻辑误判。

## 12. 传送、退出和临时状态

- 玩家退出、死亡和跨维度时按生命周期流程收纳部署对象。
- 同维度外部传送使用固定 64 格策略。
- 小于或等于附近范围时，适当保留或重新定位跟随对象。
- 超过范围时收纳坐骑，并安全处理伙伴。
- 64 格只适用于外部传送事件，不适用于玩家正常移动、下落、与生物距离或离地高度。
- 重复传送事件必须去重。
- 动画、切换、救援、座位修正和 Sable 投影使用操作锁/意图标记，不能被普通传送收纳重复处理。

## 13. 小屋系统

小屋是唯一正式 Home 系统，不保留任意坐标 Home 和通用保存位置 Home。

### 13.1 小屋数据和权限

- 玩家可以拥有多个小屋。
- 小屋方块只保存小屋 UUID、主人和展示信息。
- 居民关系保存在世界数据，不依赖在线玩家扫描。
- 一个生物只能有一个当前小屋绑定。
- 改绑新小屋会替换旧绑定，不提供历史小屋选择列表。
- 只有生物伙伴可以成为居民。
- 小屋居民没有显示数量上限，AUI 页面必须滚动。
- 小屋主人可以命名、分配、移除居民。
- 其他玩家可以打开别人的小屋，但只能查看，不能使用管理功能。
- 不支持转让、信任列表或其他玩家管理。
- 物理破坏遵循普通方块权限。
- 小屋被破坏后掉落普通未绑定小屋物品；重新放置获得全新的小屋 UUID。

### 13.2 小屋操作方式

- 右键放置的小屋直接打开对应小屋页面。
- 小屋居民分配只出现在当前小屋的主人管理页面。
- 普通仓库、详细面板、部署生物和编队右键菜单不提供通用“分配小屋”选项。
- 外部玩家查看页面为只读。

### 13.3 居民距离规则

- 主人在线、处于小屋维度且小屋区块已加载时，距离小屋 80 格以内可以实体化居民。
- 80 到 96 格之间进入宽限区，居民保持当前状态，不立即反复收纳/召唤。
- 超过 96 格后居民回到 `HOME_STORED`。
- 玩家退出、换维度或小屋区块卸载时绕过距离宽限，立即安全收纳。
- 多个相近小屋的居民不能互相重叠。
- 找不到安全且不重叠的落点时保持 `HOME_STORED`，下次重试，不能强行生成。
- 小屋被破坏时，活居民回到普通仓库；死亡居民只清除小屋绑定，保留死亡记录和睡眠复活资格。

## 14. 死亡与睡眠复活

- FindMe 保留可恢复死亡快照时，绑定生物不掉落物品，避免快照和掉落物重复。
- 睡眠不消耗物品。
- 保留现有 70% 复活概率。
- 保留每个玩家 10 分钟冷却。
- 睡眠时从有效死亡列表随机选择一个生物，不固定选择最新死亡记录。
- 有有效小屋绑定时，在该小屋附近安全复活并恢复居民逻辑。
- 没有小屋时，在睡眠玩家附近的安全随机位置复活。
- 复活前创建安全备份并校验 UUID，不能生成重复实体。
- 死亡记录永久删除和手动恢复不是同一个操作。
- AUI 死亡记录页提供查看详情和确认永久删除，不提供直接无确认复活。

## 15. AUI 管理界面

### 15.1 总体结构

使用一个 ApricityUI 管理壳，统一以下页面的布局和交互：

- 坐骑仓库。
- 载具仓库。
- 伙伴仓库。
- 编队编辑。
- 生物详细面板。
- 死亡记录。
- 多个小屋页面。
- 设置页面。
- Doctor/恢复状态页面。

管理界面通过一个可配置的 FindMe 管理按键打开。轮盘中心不作为管理界面入口。

### 15.2 页面布局

- 左侧是类别/编队导航列表。
- 右侧是当前编队成员或仓库生物卡片。
- 类别切换同时改变左侧编队和右侧仓库内容。
- 编队页面和管理页共享搜索框、筛选栏、卡片、滚动条和右键菜单。
- 不再保留旧的独立 Tab 载具入口。
- 筛选支持模组来源、实体类型、当前状态和缺失实体。
- 所有列表都有裁剪框和滚动条。
- 页面必须适配约 427x240 的 Minecraft GUI 工作区。

### 15.3 卡片操作

- 左键选择并打开详细面板。
- 右键打开状态相关的统一菜单。
- 没有卡片双击。
- 拖拽只在编队编辑模式启用。
- 菜单操作由服务器验证，危险操作必须二次确认。

统一菜单按对象状态提供：

- 召唤/收纳。
- 加入编队或移出编队。
- 编队命名、排序、自动加入切换和确认删除。
- 重命名。
- 释放绑定。
- 死亡记录详情和永久删除。
- 小屋页面的居民分配/移除。
- Doctor 恢复差异预览和确认恢复。

“释放绑定”和“永久删除死亡记录”必须是两个不同操作。释放活体前先安全放置并移除 FindMe 所有权，永久删除死亡记录则删除快照并取消未来睡眠复活资格。

### 15.4 AUI 3D 预览

AUI 没有内置生物 3D 标签，但允许注册 FindMe 自定义 `MinecraftElement`：

```text
<findme-entity uuid="...">
```

实现方式：

- 注册带 `@ElementRegister` 的 `MinecraftElement` 子类。
- 使用 `BodyRenderNodeProvider` 注册自定义 BODY 渲染节点。
- AUI/CSS 决定卡片尺寸、位置、滚动和裁剪。
- Java 使用 AUI `Rect` 获取元素实际坐标和尺寸。
- 复用现有预览实体缓存、预览 NBT 净化、缩放器、冻结姿态、Sable 截图缓存和有限预热队列。
- 3D 卡片必须放入带 `overflow: hidden` 和圆角的父容器，使用 AUI 的 mask 裁剪。
- 自定义节点先做可见性和 `Mask.getCurrentClip()` 相交检查，再解析或渲染实体。
- 离屏卡片完全停止渲染。

性能第一阶段限制：

- 详情页可以始终渲染完整 3D。
- 列表先限制同时活动的 3D 卡片为 6 到 8 个。
- 预览实体不运行 AI、不推进正常动画、不渲染阴影。
- Sable 使用截图缓存。
- 如果大型模组生物仍有性能问题，再降级为“选中/悬停动态 3D，其他使用静态缓存”。
- 不在尚未实测前增加面向玩家的画质配置。

正式管理界面之前先做一个独立 AUI 原型：滚动列表、一个 3D 卡片、圆角裁剪、左键详情和右键菜单。原型通过后转成共享组件，不能再出现第二套平行管理界面。

### 15.5 视觉风格与已验收范本

2026-07-20 的管理/编队页实机版本已由用户验收，冻结为后续全部 FindMe AUI 页面的视觉和交互范本。权威规则见 `docs/aui-design-baseline.md`，每次进行 AUI 设计、实现、修改或审查前必须完整阅读，并重新查看最终验收截图与当前管理页实现。

整体采用已经确认的明日方舟式信息层级，同时保持 Minecraft GUI 的克制尺度和 AUI 可运行性：

- 统一浅灰三层背景、近黑侧栏、青蓝选中标识、黄色数量强调和低饱和红色危险状态。
- 统一顶栏、分类标签、侧栏、标题行、大小卡片、滚动条、底部操作提示、字号和间距规则。
- 选中大卡显示完整 3D 生物，窄卡使用头部＋身体矢量剪影；矢量优先，只有无法可靠矢量化的内容才使用 PNG。
- 严格按 `427×240` 逻辑画布和已验收卡片比例设计，同时分别验收小窗口和全屏缩放。
- 参考图和已验收管理页是规格，不是宽泛风格参考；不能为小屋、死亡、详情、编辑、设置或 Doctor 再写一套近似 CSS。
- Minecraft-CSS 只作为可用 CSS 语言和局部控件参考，不整份导入；不依赖不确定支持的响应式网页特性和复杂浏览器布局。

## 16. 特效、声音和对白

### 16.1 特效

召唤、收纳和救援统一使用效果请求系统，优先级：

1. 生物个体覆盖。
2. 实体资料默认值。
3. FindMe 内置默认值。
4. 不支持的组合使用安全回退。

自定义材质/`CUSTOM_MAGIC_CIRCLE` 永远放在用户界面和枚举顺序的最后。以后新增内置效果必须放在它之前。

### 16.2 生物声音

- 生物到达声音默认开启。
- 实体资料指定声音优先于生物自身环境声音。
- 指定声音无效时回退到真实 ambient/voice sound。
- 实体明确静音时不强行播放。
- 只在实体成功显现后播放，不在预显现阶段猜声音。
- 使用合适的声音类别、音量、音调和防刷屏冷却。
- 遵守 Minecraft 声音设置。

### 16.3 文本表现

统一事件管线，提供三种模式：关闭、实用提示、沉浸式对白。

- 默认模式为实用提示。
- 沉浸式对白由玩家主动开启。
- 对白内容放到资源/数据 JSON，不继续扩大配置字段列表。

## 17. Sable 和道具

Sable 不是普通 FindMe 载具，必须保留专用兼容适配器，负责：

- 定位器/坐标绑定。
- 投影和截图预览。
- 保存和恢复。
- 座位修正。
- 切换事务。
- 乘客弹出。
- 失败回滚和清理。

保留现有木棍材质的 `vehicle_seat_cushion`，其实际作用是绑定 Sable 座位/坐标：

- 可重复使用。
- 无耐久。
- 不消耗。
- 不适用于普通载具座位。

`vehicle_binder` 是地图材质的消耗品，用于绑定并保存整个普通载具或 Sable 载具。名纸和绑定器只有成功绑定后才消耗。

配方和创造模式分类保持原来的位置。技能书在实验技能关闭时隐藏，但保留注册 ID 以避免存档兼容问题。

## 18. 技能和实验开关

技能系统不进入正式生命周期，默认关闭，并使用同步的服务器配置开关：

- 关闭时隐藏技能书和轮盘提示。
- 拒绝技能网络包。
- 关闭时安全取消并恢复正在运行的临时控制。
- 技能 performer 必须带临时标记，不能进入仓库、编队、死亡记录、备份或 Doctor 正式生物扫描。

实现状态（2026-07-23）：

- [已完成] 关闭时创造栏隐藏技能书但保留物品注册 ID；C 指令轮盘同时移除技能和运输动作，不留下禁用占位。
- [已完成] 运行中关闭配置会在服务器 tick 取消全部技能临时控制、移除 performer，并按原记录恢复技能来源生物。
- [待实机验收] 分别在启动前关闭、运行中关闭和重新开启三种状态下确认创造栏、C 轮盘、网络拒绝和生物恢复表现。

## 19. Doctor、备份和恢复

### 19.1 权限

- 玩家可以检查和恢复自己的生物。
- 管理员可以检查和恢复所有玩家。
- 普通玩家不能修改实体资料或放宽绑定条件。

### 19.2 自动修复

只允许自动修复纯结构问题，例如：

- 重复或缺失的编队引用。
- 有明确有效状态时的过期部署标记。

自动修复之前必须：

1. 创建安全备份。
2. 写入恢复日志。
3. 记录修复前后状态和原因。

以下操作永远需要差异预览和明确确认：

- 创建实体。
- 替换实体。
- 删除实体。
- UUID 冲突处理。
- 反序列化快照。
- 删除死亡记录。
- 整个玩家回滚。

缺失实体类型保留为 `RECOVERY`，等待对应模组回来或玩家明确选择破坏性处理。

### 19.3 备份策略

- 全玩家世界数据每 30 分钟自动备份。
- 保留最近 5 个全玩家备份。
- 破坏性操作前强制备份。
- 每个生物保留有界的恢复墓碑，最多保留最近 30 条。
- 恢复墓碑不是普通仓库，也不作为玩家日常管理列表。
- 备份包含格式版本和校验和。
- 校验和不匹配时禁止恢复。
- 恢复默认是预览，必须显式 `confirm` 才会修改。
- 恢复、清锁、临时实体清理、释放绑定和死亡记录删除失败时不得继续变更。

## 20. 配置和指令

保留：

- 一个可配置的管理界面按键。
- 骑乘/载具轮盘按键。
- 伙伴轮盘按键。
- 伙伴部署上限配置，默认 2。
- 实验技能同步开关，默认关闭。
- 声音、实用提示和沉浸式对白设置。
- 实体资料编辑和整合包资料工具。
- Doctor、备份和恢复工具。
- 管理员准星强制绑定。

删除或不再提供：

- 旧管理界面 G 键。
- 旧库存 F 按钮入口。
- 普通玩家使用 `/findme mount` 和 `/findme companion` 管理生物的重复指令。
- 任意坐标 Home 指令。
- 旧 Emergency Rescue 独立指令/服务。
- 旧的自动忽略、黑名单和分散移动配置。

所有保留指令必须调用与 AUI 相同的生命周期事务，不能实现第二套召唤/收纳逻辑。

## 21. 安全不变量

实现和代码审查必须持续满足：

- 正式实体删除前已经写入并验证快照。
- 载具和 Sable 删除前已经写入并验证对应快照/蓝图。
- 生物死亡前先创建安全备份。
- 任何危险操作都检查操作锁、保存中状态和到达中状态。
- 一个 UUID 不能同时出现在世界和正式仓库。
- 临时技能实体和临时座位实体不能成为正式生物。
- 失败恢复不能静默丢弃记录。
- 数据迁移失败时旧数据保持不变并可重试。
- Doctor 默认只读；自动修复必须有备份和日志。
- 释放绑定、永久删除死亡记录和恢复操作必须二次确认。
- 普通 UI、网络包和指令不能绕过生命周期 facade 直接删除或恢复正式实体。
