## 0. 强制阅读规则

每次设计、实现、修改或审查 FindMe 的 AUI 页面之前，必须完整阅读本文件，并重新查看上面的最终验收截图和当前管理页实现。不能只凭记忆复刻，也不能跳过对比直接编码。

管理页已经验收通过。除非用户明确要求或发现真实回归，不再重构、换风格或重复检查该页；后续页面从它抽取和复用规则。

## 1. 我们最终学到的原则

1. 参考图是规格，不是宽泛的“风格参考”。字号、留白、颜色层级、分割线、卡片比例、模型遮挡关系和选中标识都需要逐项对比。
2. 先确定构图，再写代码。新页面先给出与管理页同一视觉系统的概念图或线框，确认后才实现，避免在代码里反复试错。
3. 先建立稳定的大结构，再微调局部。顺序固定为页面骨架、区域比例、卡片层级、文字层级、交互状态、最后才是 1～4 像素微调。
4. 留白、对齐和信息层级比装饰更重要。看起来“不统一”通常不是缺少装饰，而是边距、基线、字号和分割关系没有统一。
5. 视觉对齐要按最终画面判断，不只按 CSS 数值判断。不同字体的字面框、AUI 缩放和实体模型会造成视觉偏差，必要时允许 1～4 逻辑像素的光学补偿。
6. 所有页面必须共享一套壳、色板、字体层级、卡片、滚动条、选中标识和操作提示，不能给小屋、死亡、编辑、设置或 Doctor 各写一套“差不多”的 CSS。
7. 矢量优先。分割线、鼠标图标、箭头、剪影、角标和几何装饰使用 AUI/CSS 的边框、圆角、渐变和 `clip-path`；只有真正无法可靠绘制的内容才使用 PNG，且不能用低分辨率位图放大。
8. 页面必须展示真实同步数据。名字、状态、分类总数、编队占用数和按钮可用状态不能为了还原参考图而伪造。
9. 模型是内容，不是背景装饰。只在选中大卡显示完整 3D；窄卡使用清晰的头部＋身体矢量剪影。按钮和文字必须位于模型前方，模型必须被卡片裁剪。
10. 小窗口和全屏是两个必须分别验收的布局状态。某个位置在 427×240 下正确，不代表 GUI 放大后仍正确；依赖缩放后父容器宽度的位置必须由 Java 输出实际逻辑像素。
11. 构建成功只证明能编译，不等于视觉完成。视觉完成必须经过实机截图、与范本逐项对比，并由用户确认。
12. 已验收内容冻结。后续工作复用它，不再为了“顺便优化”而打开已经结束的微调循环。

## 2. 统一画布与几何基准

所有页面先按 Minecraft 默认 GUI 的 `427 × 240` 逻辑像素设计：

| 区域 | 基准 |
| --- | --- |
| 顶栏 | 35px 高 |
| 左侧栏 | 75px 宽 |
| 主区左内边距 | 10px |
| 选中大卡 | 136 × 141px |
| 窄卡 | 36 × 141px |
| 卡片间距 | 3px |

这些值是共享视觉比例，不应在每个页面重新猜一遍。需要响应不同 GUI 缩放时，由 Java 计算动态尺寸并通过 CSS 变量输出，不在 HTML 中复制另一套比例。

## 3. 色彩与背景层级

管理页不是单色灰底，而是三个明确层级：

- 页面底：浅灰绿 `#e3e7e6`，叠加克制的深灰和白色斜向区域。
- 顶栏：更浅的半透明灰 `rgba(237, 240, 239, 0.97)`，与页面主体有细分割。
- 侧栏：近黑蓝灰 `rgba(25, 33, 38, 0.99)`，形成最强结构锚点。
- 选中大卡：近黑蓝灰 `#10191d`，用轻微渐变建立前后层次。
- 主强调：青蓝 `#16b5df`，只用于当前分类、选中项、关键分隔和主操作。
- 数量强调：黄色 `#f1c94d`。
- 危险操作：低饱和红色，不与普通状态共用青蓝色。

不要加入页面两侧悬空的黑色半透明大背景，也不要把整个页面铺成一个颜色。分割线保持细、淡、有用途；不使用网页后台式粗卡框和大阴影。

## 4. 字体层级

不能给整页统一一个小字号再依赖缩放。管理页当前字号是后续页面的起始标尺：

| 内容 | 基准字号/规则 |
| --- | --- |
| 中文页面标题 | 23px、加粗 |
| 英文副标题 | 7px，宽度允许略松 |
| 顶部分类 | 11px，当前分类加粗 |
| 侧栏编队名称 | 12px |
| 侧栏序号 | 20px、常规字重 |
| 主区两位序号 | 31px、Arial、常规字重 |
| 主区标题/副标题 | 16px / 8px |
| 选中卡注册名称 | 30px，必须清晰可读 |
| 窄卡名称/状态 | 23px 加粗 / 9px |
| 底部操作提示 | 10px |
| 编队数量 | 18px 主数＋7px 总数 |

长名称优先做裁剪、可用宽度调整或详情展示，不允许为了一个长名称把整页文字重新缩小。大号字需要给足容器高度，避免 AUI 字体先栅格化再缩放时出现溢出和发糊。

## 5. 对齐和选中状态

- 顶部当前分类下方必须有 2px 青蓝横线，并与分类文字居中。
- 左侧当前编队必须有独立的 2px 青蓝短竖线；竖线与侧栏边缘、队伍卡和右侧卡片的青蓝基线都要保留明确间隙。
- 主区两位序号右侧使用 2px 青蓝分隔线。序号区域和右侧标题区域必须具有相同的视觉高度与上下留白。
- 左侧序号、编队名和占用数按共同基线排列，不能各自漂移。
- 底部数量靠右，并与卡片右边界和操作提示基线对齐。
- 所有 1～4px 的最终位置修正应记录为光学补偿，不要在别的页面机械复制一个脱离上下文的偏移量。

## 6. 卡片和 3D 预览

- 同一编队一页最多六个位置，与轮盘容量一致。
- 第一张选中卡使用完整 3D 预览、名称、状态和主/次操作；其余位置为窄卡。
- 窄卡必须保留“头＋身体”的完整矢量轮廓，不能只画躯干；高光斜带的位置与卡片一致，不跟随模型随机漂移。
- 只有被选中的卡显示动态完整模型，避免六个实体同时抢占视觉和性能。
- 召唤、详情等按钮的 `z-index` 必须高于模型和卡片渐变遮罩。
- 预览元素放在裁剪父容器内；父容器负责 `overflow: hidden` 和圆角，不能假设自定义预览节点会裁剪自己的 BODY。
- 大型、超高、超宽、multipart 生物和 Sable 必须继续使用共享预览缩放、净化 NBT、缓存和降级路径，不能为某一页新写预览实现。

## 7. 侧栏和滚动条

- AUI 原生滚动条的外观不能可靠用普通 CSS 改成目标样式，因此侧栏使用隐藏原生滚动条＋AUI 滚动模型＋自定义滑块。
- 自定义滑块为 1px 细条，位于侧栏列表右侧的独立间隙中，不能压在队伍卡片上。
- 滑块位置和长度来自真实内容高度、视口高度和滚动进度；短列表不伪造滚动状态。
- 全屏时侧栏实际宽度会被 Java 放大，滚动条横坐标必须按实际缩放宽度计算，不能使用只在小窗口正确的固定 `left`。
- 列表必须有裁剪范围，新增无限编队不能溢出侧栏。

## 8. AUI 实现边界

- AUI 不是浏览器。只使用当前版本明确支持的标签、CSS 和 DOM API，不依赖浏览器默认样式或未确认的 Web API。
- HTML/CSS 负责结构、布局、滚动、裁剪和视觉状态；Java 负责同步 DTO、真实数据、事件、生命周期动作、3D 实体渲染和缩放后关键像素值。
- 固定壳优先，列表/卡片只在同步版本、分类、选中项、搜索或筛选变化时更新，不能每帧重建 DOM。
- 关键文字显式包裹在元素中，不依赖裸文本节点和不稳定的语义标签。
- 绝对定位以父元素内容框为准。绝对定位装饰不能作为普通 flex 子项插入顶栏，否则可能改变整条顶栏布局。
- 任何动态 `setInnerHTML` 后都要按现有实现重建选择器索引并重应用缓存样式。
- 管理页、小屋页、死亡页、详情页、编辑页、设置页和 Doctor 页必须复用共享 shell/style tokens；后端动作可以不同，外观和操作语言不能分叉。

## 9. 每次 AUI 工作的固定流程

1. 完整阅读本文件。
2. 查看最终验收截图、当前 `manager.html` 和 `FindMeAuiManageScreen.java`。
3. 列出当前页面与范本在结构、字号、颜色、分割线、间距、数据和层级上的差异。
4. 新页面先提交概念图/线框并取得确认；旧页面修复先复述具体差异。
5. 优先抽取或复用现有 shell、tokens、卡片、提示、滚动和预览组件，不复制整份 CSS。
6. 一轮只处理一个明确层级的问题，避免同时改结构、字体和数据造成回归难以定位。
7. 构建并部署到指定测试实例。
8. 分别取得小窗口和全屏实机截图，与范本逐项对比。
9. 通过边界状态检查后再请求验收；用户确认后将该页面标记已完成并冻结。

## 10. 每页验收清单

- 小窗口与全屏均无重叠、漂移、底部空块或裁剪错误。
- 空数据、一个条目、六个条目、超长列表和滚动到底均正常。
- 长中文名、长英文名、缺失翻译和不同 GUI 缩放下文字仍可读。
- 大型模组生物、multipart 生物、Sable、缺失实体类型不会越界或拖垮页面。
- 当前分类、当前队伍、当前卡片三个选中状态清晰但不过度抢眼。
- 分类总数、编队占用数、名字、状态和操作可用性全部来自真实同步数据。
- 模型、按钮、文字、遮罩和菜单的前后层级正确。
- 搜索、滚动、左键、右键、确认和返回操作与其他 AUI 页面一致。
- 首次打开、首次同步、切换分类和删除当前条目后不会显示旧数据。
- `build` 通过；视觉还必须由实机截图和用户确认完成。

## 11. 明确禁止

- 不凭记忆做“差不多”的明日方舟风格。
- 不恢复旧 Java 管理页或第二个载具管理入口。
- 不为每个页面复制一整套近似 CSS。
- 不用低清 PNG 代替能稳定矢量绘制的几何元素。
- 不为了对齐参考图而写假名称、假数量或假状态。
- 不用构建成功代替视觉验收。
- 不在已验收页面上进行未被要求的整体重构。
